“The Bridge” vs. today's Marketplace

This is a naming collision worth flagging on its own: the (marketplace) module already in the codebase is a conventional buy/sell goods store, not the skills-and-opportunity exchange the design brief calls The Bridge.

The brief is explicit that “marketplace” was deliberately avoided as a name because of its buy-and-sell connotation. Building Bridge features (mentorship matching, talent discovery, paid gigs, Cap-weighted visibility) directly on top of the existing Product/Order tables risks conflating a commerce feature with a reputation feature the spec is careful to keep separate.

Priority A backlog — all shipped

The five load-bearing items from the original audit are now implemented. Remaining work is polish (soft-language earnings copy, admin-gate hardening) and screen-by-screen frontend wiring.

  1. Volunteer/mentor opt-in flag Done

    Profile.isVolunteerMentorOptIn gates volunteer apply, hour logging, and mentorship calls. Set via onboarding (POST /choices) or PATCH /user-profile/volunteer-mentor-opt-in.

  2. Calling mentorship dimension Done

    Calling.callPurpose (GENERAL vs MENTORSHIP) auto-creates a pending VolunteerHour on mentorship call end; mentee confirms for Cap credit.

  3. Mutual-Connect gating on messaging Done

    FriendRequestService.assertConnected enforced server-side on private chat create/send (HTTP + socket) and callPurpose=GENERAL calls.

  4. Sky Blue rename + parallel track Done

    CapLevel.SKY_BLUE with SkyBlueNomination workflow; invitation-only, KYC + notability, earns at Red rate until Black-level volunteering.

  5. Bridge as separate module Done

    (bridge) module with expertise/gig/project-help listings, Cap-weighted discover, booking + transaction fee — separate from goods Product/Order.
